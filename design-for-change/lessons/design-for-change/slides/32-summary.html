1 Different organizations of functionality into elements lead to different design decisions being modularized and hidden behind interfaces
2 Technical dependencies require coordination between people, or defects may result (Conway's Law)
3 Localizing changes using interfaces and adapters minimizes the impact of change
4 Technical debt is when developers break the design for later fix — must be managed
5 Code decay is when implementation diverges from design — prevent with code reviews
Design for change is not about predicting the future — it's about making the system resilient to whatever changes come.
