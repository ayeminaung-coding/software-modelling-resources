Exercise: Apply Modifiability Tactics

Scenario: Legacy Monolith Refactoring

Match each problem to the most appropriate modifiability tactic

Your company has a monolithic e-commerce application. Every feature change requires modifying multiple parts of the codebase and a full redeployment. The team wants to improve modifiability.

Available Tactics

Maintain Semantic Coherence Abstract Common Services Hide Information Generalize Modules Use Intermediaries
1
Payment logic is scattered across 5 different modules
Why: Consolidate all payment code into a Payment Service/Module to maintain semantic coherence.
2
All modules directly access the same database tables
Why: Create domain services that own their data and access only through APIs - hiding the database implementation details.
3
Email templates are hardcoded in 12 different places
Why: Create a centralized Notification/Template Service - abstracting the common email functionality.
4
Business rules change frequently but require code changes
Why: Use a rules engine or configuration to externalize business rules - generalizing the module to handle rule changes without code changes.
