Analysis Method Comparison

Each analysis method serves a different purpose. Choose based on what questions you need to answer about your architecture.

Method When to Use Inputs Outputs Effort
Use Case Analysis Early design phase; validating functional coverage and identifying architecture-relevant scenarios Use cases, user stories, domain model Architecture scenarios, prototypes, risk areas Low
QA Analysis After initial design; verifying the architecture meets quality requirements QA scenarios, SLAs, architecture views Metrics, compliance reports, gap analysis Medium
Trade-off Analysis When choosing between design alternatives that favor different quality attributes Design options, QA priorities, stakeholder concerns Decision records, ranked alternatives, rationale Medium
Cost-Benefit Analysis Before committing resources; justifying architecture investments to stakeholders Cost estimates, benefit projections, risk factors ROI, break-even point, risk-adjusted estimates High
💡

In practice: Start with Use Case Analysis to understand scope, use QA Analysis to validate design, apply Trade-off Analysis at decision points, and use CBA for major investment decisions. They complement each other across the architecture lifecycle.
