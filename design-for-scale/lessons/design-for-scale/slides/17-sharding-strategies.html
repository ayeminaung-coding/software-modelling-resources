Database Sharding Strategies

Range-Based Sharding

Partition by value ranges (e.g., user_id 1-1000, 1001-2000)

  • Simple to implement
  • Uneven distribution

Hash-Based Sharding

Use hash function: shard = hash(key) % num_shards

  • Even distribution
  • Hard to add shards

Directory-Based Sharding

Lookup table maps keys to shards

  • Flexible mapping
  • Lookup overhead

Geographic Sharding

Partition by user location or region

  • Low latency
  • Cross-region queries
Consistent Hashing: Minimizes data movement when adding/removing shards. Essential for dynamic scaling.
