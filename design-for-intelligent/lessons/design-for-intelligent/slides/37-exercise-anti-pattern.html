❌ Anti-Pattern A: Model loaded per call (Line 4)
Loading model inside a function = reload on every call. At 1000 requests/second, loading a 200MB model each time is catastrophic. No version tracking, no injection â€” impossible to swap models.
⚠ Anti-Pattern B: Silent approval on failure (Lines 10-11)
No timeout, no error handling, silent approval on failure = worst possible fallback. If the model crashes or returns None, every expense is automatically approved â€” fraud walks through.
👁 Anti-Pattern C: No inference logging (Lines 13-15)
No logging of score, decision, latency, or model version. Cannot audit, debug, or detect drift. Everything "works" but you're flying blind in production.
