Hidden Technical Debt in AI Systems

Based on Sculley et al. (Google, NIPS 2015) — "Hidden Technical Debt in Machine Learning Systems"
🕸 Entanglement
Changing any input feature changes the behavior of all other features (CACE: Changing Anything Changes Everything).
Adding "merchant_country" to the fraud model changes how "amount" is weighted. No safe way to add features without retraining and re-evaluating everything.
🔗 Correction Cascades
Model A feeds Model B. Error in A compounds in B.
Category Classifier → Fraud Detector. If Category Classifier mislabels "hotel" as "other", Fraud Detector sees wrong features → cascades wrong fraud score.
👤 Undeclared Consumers
Other systems start using your model's output without telling you.
The fraud score starts being used by the approver workflow AND the reporting dashboard AND a compliance check â€” none of which the ML team knows about. Model update breaks all three.
🌿 Pipeline Jungle
Data preparation code grows organically: scripts calling scripts, no owner, no tests.
Nobody knows where the feature engineering script came from. It runs in a cron job somewhere. If you touch it, the model breaks. "Dead code" feeds features no one uses anymore.
